静态图整网变异的精度对齐进展
一、概述
针对静态图整网变异和基于pta的MindSpeed整网泛化精度对齐，我们使用了以下手段完成两者的对齐：
1.开启硬件确定性
2.权重转换
3.参数对齐（使用自定义的参数映射表进行同等效果参数的转换）
4.可计算参数对齐（通过间接计算得到一些不能映射参数的值）

二、对齐细节
（一）开启硬件确定性
  使用了如下参数开启硬件确定性，保证能够排除硬件侧的问题：
export HCCL_DETERMINISTIC=true  # HCCL确定性
export ASCEND_LAUNCH_BLOCKING=1  # 硬件确定性
export NCCL_DETERMINISTIC=1

本部分实际执行操作：
1. 在 PTA 相关任务启动前统一 `source scripts/envset/pta.sh`，由该脚本注入上述确定性环境变量。
2. 运行时生成的 `pta-save_iter*.sh / pta-load_iter*.sh` 脚本中同样会显式导出这三个变量，保证每轮迭代执行环境一致。

（二）权重转换
由于pta侧是使用megatron形式的训练方法，因此保存和加载的权重使用的是mg格式，为了保证两边模型从同样的初始化权重起步，因此采取了转换权重的办法
权重转换使用了MindSpeed-LLM提供的权重转换脚本，将pta MindSpeed-LLM产生的pth格式（内部为pkl分布式协议）的权重转换为mindformers支持的hf格式safetensors。
通过这种方式，可以保证动态图和静态图在进行pretrain时，是从完全相同的参数开始的，保证了参数初始化的对齐。
当前转换链路里，Task1 会走 `convert.sh + convert_ckpt.py`，并显式带上目标 TP/PP/EP 规格；这样做的好处是，权重格式和并行切分会一起对齐。

本部分实际执行操作：
1. Task1 在 `utils/task/task1.py` 中调用权重转换入口，先解析本地 `scripts/runtime/convert.sh` 与 `utils/runtime/convert_ckpt.py`。
2. 运行转换命令（示例）：
  `bash scripts/runtime/convert.sh --load-model-type mg --save-model-type hf --load-dir <pta_ckpt_dir> --save-dir <mf_ckpt_dir> --model-type-hf <model> --target-tensor-parallel-size <tp> --target-pipeline-parallel-size <pp> --target-expert-parallel-size <ep>`。
3. 转换日志写入 `output/<run>/iters/iter_*/runtime_logs/mf_convert_iter*.log`，可用于核对实际使用的模型别名与并行规格。

（三）参数映射对齐
由于两者的训练脚本存在格式上的差异，因此自然需要进行一层转换。并且在部分参数上，存在“参数名的不同，但实际语义相同”的情况。因此我们使用一张转换表，用映射的方式转换这部分参数。（映射表详见assets/runtime/configs/mf_converter_mapping.yaml）
目前映射表已经覆盖了这几类核心字段：

1. 模型结构参数：`hidden_size`、`num_layers`、`num_attention_heads`、`num_key_value_heads`、`ffn_hidden_size`、`head_dim`。
2. 激活与注意力参数：`hidden_act`、`qk_layernorm`、`qkv_concat`、`use_flash_attention`、`add_bias_linear`、`attention_bias`。
3. 位置编码与词表参数：`seq_length`、`max_position_embeddings`、`rotary_base`、`vocab_size`、`padded_vocab_size`。
4. 优化器与训练参数：`lr`、`min_lr`、`weight_decay`、`adam_beta1`、`adam_beta2`、`lr_warmup_fraction`、`lr_decay_style`。
5. 并行参数：`tensor_model_parallel_size`、`pipeline_model_parallel_size`、`context_parallel_size`、`expert_model_parallel_size`、`sequence_parallel`、`use_distributed_optimizer`。

这里最关键的是两类“对齐语义”：

1. 直接映射字段会原样写入 MF YAML，例如 `PTA.seq_length -> MF.model.model_config.seq_length`。
2. 推导字段会通过转换器规则补齐，例如 `PTA.num_query_groups -> MF.num_key_value_heads`、`PTA.kv_channels -> MF.head_dim`、`PTA.disable_bias_linear -> MF.add_bias_linear`。

本部分实际执行操作：
1. 使用参数转换器命令：`python -m utils.runtime.mf_converter -i <pta_sh> -o <mf_yaml> -m <model> --template assets/runtime/mf_templates/<model>.yaml --train-iters <n>`。
2. 转换器读取 `assets/runtime/configs/mf_converter_mapping.yaml` 的 `arg_mapping`，将 PTA 参数写入对应 MF YAML 路径。
3. 产物 YAML 可直接用于 MF 训练脚本执行，日志可在 `mf_script_gen_iter*.log` 中回查。
（四）参数计算对齐
由于部分参数megatron/mindspeed这些框架会在内部进行自动计算，而不是以显示配置的方式出现，但这些参数可能在mf中需要显式进行配置声明。
对于没有显式同名目标的参数，我们不再简单忽略，而是尽量从 PTA 侧已有信息推导，例如以下：
1. `num_key_value_heads` 优先按 `group_query_attention + num_query_groups` 推导；如果没有明确组信息，则退回到 `num_attention_heads`。
2. `head_dim` 优先使用 PTA 的 `kv_channels`；如果没有，则按 `hidden_size // num_attention_heads` 推导。
3. `tie_word_embeddings` 与 `untie_embeddings_and_output_weights` 保持互补语义，避免只改一侧开关。
4. 当 `context_parallel > 1` 时，强制打开 `use_flash_attention`，避免出现“PTA 可跑、MF 直接因约束失败”的情况。

本部分实际执行操作：
1. 不需要单独命令，推导逻辑在 `python -m utils.runtime.mf_converter` 执行过程中自动触发。
2. 重点规则由转换器在读取 PTA 参数后即时回填到 MF 配置（如 `num_key_value_heads`、`head_dim`、`add_bias_linear`、`use_flash_attention`）。
3. 建议在转换后检查生成的 MF YAML 中上述字段是否与 PTA 语义一致，再进入训练阶段。
