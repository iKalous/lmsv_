# Task2 扩展说明：模块内新模块接入

## 1. 文档目的

本文面向后续开发者，说明如何把新的模块能力接入 **Task2 模块内变异**。  
Task2 的目标是：**先实例化出完整的 TransformerBlock，再根据子模块编号提取并执行指定子模块**，从而在细粒度模块级别开展变异与差分验证。

本文按两条链路展开：

- 动态图链路：`pta_msa`
- 静态图链路：`pta_mf`

---

## 2. Task2 的基本分层

无论接入动态图还是静态图，建议都按下面四层检查问题：

1. **配置入口层**  
   `genconf.py` / `webui.py` / `config.json` 是否能接收并传递新模块参数。

2. **任务编排层**  
   `utils/task/task2.py` 是否正确调用对应运行脚本。

3. **图构建层**  
   子模块编号是否能在图构建逻辑中映射到正确的实际模块。

4. **对齐校验层**  
   PTA、MSAdapter、MindFormers 的验证脚本是否能正确加载和执行对应子模块。

---

## 3. 动态图链路扩展（`pta_msa`）

### 3.1 适用范围

动态图模块内扩展主要涉及以下目录：

- `utils/task/*`
- `utils/runtime/mutate_and_forward/*`
- `assets/runtime/*`
- 配置入口：`genconf.py` / `webui.py` / `config.json`

图构建核心文件：

- `utils/runtime/core/subgraph.py`

执行与校验核心文件：

- PTA：`utils/runtime/mutate_and_forward/load_and_forward_submodule-auto.py`
- MSAdapter：`utils/runtime/ms_mutate_and_forward/load_and_forward_submodule.py`

这两个运行脚本在职责上是对应关系。若接入逻辑需要改动，通常应同步检查两侧。

### 3.2 接入步骤

#### 步骤 1：准备模型模板配置

新模型首先要补到：

```text
assets/runtime/model_config/<model>.yaml
```

Task2 会基于该配置先实例化完整的 TransformerBlock，再根据用户指定的 `SUBMODULES` 从中提取对应子模块。

#### 步骤 2：扩展子模块编号范围

当前入口通常把 `SUBMODULES` 限制在 `0~10`。  
如果新增子模块编号超出该范围，需要同步放宽入口校验。

`genconf.py` 示例：

```python
submodules = ask_int_list(
    "SUBMODULES（取值范围 0~11）",
    default_submodules,
    min_value=0,
    max_value=11,
)
```

`webui.py` 后端校验示例：

```python
task2_submodules = _ensure_int_list(
    task2_raw.get("SUBMODULES"),
    "任务2 SUBMODULES",
    min_value=0,
    max_value=11,
)
```

前端校验示例：

```javascript
if (value < 0 || value > 11) {
  throw new Error(`${field.label} 取值范围必须在 0~11 之间`);
}
```

#### 步骤 3：在 `subgraph.py` 中补齐子模块映射

核心位置：

```text
utils/runtime/core/subgraph.py
```

需要在 `Graph.load(...)` 的 `submodule_num` 分支中，把新增编号映射到真实模块对象。

现有映射示例：

- `0`：`input_layernorm`
- `1`：`self_attention`
- `2`：`self_attention.core_attention`
- `5`：`self_attention.linear_proj`
- `6`：`self_attention.linear_qkv`
- `8`：`mlp`
- `9`：`mlp.linear_fc1`
- `10`：`mlp.linear_fc2`

示例写法：

```python
submodule_num = node.block_num
if submodule_num == 0:
    node.block = transformer_block.layers[0].input_layernorm
elif submodule_num == 1:
    node.block = transformer_block.layers[0].self_attention
elif submodule_num == 2:
    node.block = transformer_block.layers[0].self_attention.core_attention
elif submodule_num == 8:
    node.block = transformer_block.layers[0].mlp
elif submodule_num == 9:
    node.block = transformer_block.layers[0].mlp.linear_fc1
elif submodule_num == 10:
    node.block = transformer_block.layers[0].mlp.linear_fc2
elif submodule_num == 11:
    node.block = transformer_block.layers[0].post_attention_layernorm
```

如果这里没有补映射，Task2 即使拿到了新编号，也无法正确落到目标子模块。

### 3.3 动态图链路检查清单

#### 配置检查

- `COMPARE_MODE=pta_msa`
- 模型名可被配置入口接受
- 新子模块编号可被配置入口接受

#### 任务调用检查

- `task2.py` 是否调用 `load_and_forward_submodule-auto.py`
- MSAdapter 链路是否调用 `load_and_forward_submodule.py`

#### 结果文件检查

- `res/submodule_execution_pta.csv`
- `res/submodule_execution_msa.csv`
- `res/training_log_pta/training_log-<iter>.csv`
- `res/training_log_msa/training_log-<iter>.csv`

#### 日志检查

- `output/<timestamp>/iters/iter_i/runtime_logs/pta_iter{i}.log`
- `output/<timestamp>/iters/iter_i/runtime_logs/msa_iter{i}.log`

建议重点搜索：

- `RuntimeError`
- `attention配置严格对齐失败`

## 4. 静态图链路扩展（`pta_mf`）

### 4.1 适用范围

静态图模块内扩展主要涉及：

- `utils/task/*`
- `utils/runtime/mf_mutate_and_forward/*`
- `assets/runtime/*`
- 配置入口：`genconf.py` / `webui.py` / `config.json`

图构建核心文件：

- `utils/runtime/mf_mutate_and_forward/sub_graph.py`

执行与校验核心文件：

- `utils/runtime/mf_mutate_and_forward/load_and_forward_submodule.py`

### 4.2 接入步骤

#### 步骤 1：扩展子模块编号范围

与动态图链路一致。如果新增子模块编号超出当前 `0~10` 范围，需要同步修改 `genconf.py` 与 `webui.py` 的校验逻辑。

#### 步骤 2：在 MF 子图中补齐子模块映射

核心位置：

```text
utils/runtime/mf_mutate_and_forward/sub_graph.py
```

同样需要在 `Graph.load(...)` 的 `submodule_num` 分支中增加映射。例如：

```python
submodule_num = node.block_num
if submodule_num == 0:
    node.block = transformer_block.layers[0].input_layernorm
elif submodule_num == 1:
    node.block = transformer_block.layers[0].self_attention
elif submodule_num == 2:
    node.block = transformer_block.layers[0].self_attention.core_attention
elif submodule_num == 8:
    node.block = transformer_block.layers[0].mlp
elif submodule_num == 9:
    node.block = transformer_block.layers[0].mlp.linear_fc1
elif submodule_num == 10:
    node.block = transformer_block.layers[0].mlp.linear_fc2
elif submodule_num == 11:
    node.block = transformer_block.layers[0].post_attention_layernorm
```

#### 步骤 3：必要时补 `construct(...)` 的形状处理

如果新增子模块对输入形状有特殊要求，仅补 `node.block` 映射通常不够，还要在 `construct(...)` 中补对应分支。示例：

```python
elif submodule_num == 11:
    hidden_size = cur_node.config.hidden_size
    input_data = reshape_tensor_nd(
        input_data,
        (input_data.shape[0], input_data.shape[1], hidden_size),
    )
    output = cur_block(input_data)
```

否则运行时很容易直接出现维度错误。

#### 步骤 4：如需引入新的 decoder 类或算子，补充 `OperatorSet.py`

如果新模块需要参与随机插入或变异候选，还要检查：

```text
utils/runtime/OperatorSet.py
```

例如：

```python
llm_operators = {
    "Qwen2DecoderLayer",
    "ChatGLMDecoderLayer",
    "YourNewDecoderLayer",
}

insert_operators = {
    *activation_operators,
    *seq_math_operators,
    *llm_operators,
}
```

#### 步骤 5：准备 MF 模板配置

建议新增：

```text
assets/runtime/mf_templates/<model>.yaml
```

并在 Task2 配置中传入：

```json
{
  "tasks": {
    "2": {
      "COMPARE_MODE": "pta_mf",
      "MF_ARGS_PATH": "assets/runtime/mf_templates/your_model.yaml",
      "ENABLE_MF_WEIGHT_LOAD": false
    }
  }
}
```

Task2 最终会把这些参数传给：

```bash
python utils/runtime/mf_mutate_and_forward/load_and_forward_submodule.py \
  --load-path <mutating-json> \
  --args_path assets/runtime/mf_templates/your_model.yaml \
  --train-iters <iters>
```

#### 步骤 6：先关闭严格权重加载，后做一致性验证

建议先用：

- `COMPARE_MODE=pta_mf`
- `ENABLE_MF_WEIGHT_LOAD=false`

先打通最小流程，再切换为 `true`，验证权重加载与数值一致性。

### 4.3 静态图链路检查清单

#### 配置检查

- `COMPARE_MODE=pta_mf`
- `MF_ARGS_PATH` 指向有效模板
- 新子模块编号与模型名可被入口接受

#### 任务调用检查

- `task2.py` 是否调用 `load_and_forward_submodule.py`

#### 结果文件检查

- `res/submodule_execution_mf.csv`
- `res/training_log_mf/training_log-<iter>.csv`

#### 日志检查

- `output/<timestamp>/iters/iter_i/runtime_logs/mf_iter{i}.log`

建议重点搜索：

- `RuntimeError`
- `attention配置严格对齐失败`
- `decoder配置严格对齐失败`

#### 对齐开关（按需）

- `LMSV_ALIGN_ADD_QKV_BIAS`
- `LMSV_STRICT_ATTN_CONFIG_MATCH`
- `LMSV_STRICT_ATTN_PARAM_LOAD`
- `LMSV_STRICT_DECODER_CONFIG_MATCH`

---

## 5. 推荐接入顺序

无论是动态图还是静态图，建议都按下面的顺序推进：

1. 先在 Task2 打通单子模块；
2. 再在需要时迁移到 Task3 组合图；
3. 最后再打开严格对齐开关做回归门禁。

这样做的好处是：Task2 的问题面最小，能更快判断是入口问题、映射问题，还是运行时问题。

---

## 6. 常见问题

### 6.1 新编号已放开，但仍找不到模块

大概率不是入口问题，而是 `subgraph.py` / `sub_graph.py` 中没有补 `submodule_num -> node.block` 映射。

### 6.2 映射补了，但运行时仍维度报错

优先检查 `construct(...)` 是否为该子模块补了对应的形状处理逻辑。

### 6.3 PTA 能跑，MF 不能跑

优先检查：

- `MF_ARGS_PATH` 是否有效；
- `sub_graph.py` 是否补了同样的映射；
- `OperatorSet.py` 是否遗漏；
- 是否启用了过早的严格对齐或权重加载开关。

### 6.4 CSV 没有结果，但日志目录存在

说明任务已启动，但执行链路中途失败。优先从 `runtime_logs` 中定位第一个真实异常，而不是只看最终结果文件。

---

## 7. 结论

Task2 的核心不是“新增一个编号”，而是**让这个编号在配置入口、图构建和执行链路上都能闭环**。

判断是否真正接入成功，至少要满足三点：

1. 配置入口能够接受该编号；
2. 图构建逻辑能够把编号映射到真实模块；
3. 对应运行脚本能够正确执行并产生结果文件。
