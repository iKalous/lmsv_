# Task6 扩展说明：多模态整网变异扩展

## 1. 文档目的

本文面向后续开发者，说明如何扩展 **Task6 多模态整网变异与验证**，使工具能够支持新的多模态模型，并在 PTA / MSA /（按需）MF 链路上完成配置变异、真实执行与结果对比。

原始资料中，Task6 的描述同时出现了两类入口视角：

- 模型侧执行链路：`mm-new/net_mutation/*`、`mm-new/pretrain_examples*`
- 当前任务编排入口：`utils/task/task6.py`、`utils/runtime/mm_mutation/mm_mutator.py`

整理后，本文统一按“**任务入口 -> 模型配置 -> 运行脚本 -> 变异参数 -> 可选静态图支持**”的顺序说明。

---

## 2. Task6 的主链路

### 2.1 当前任务编排入口

Task6 的核心入口位于：

```text
utils/task/task6.py
```

当前一轮执行通常包括：

1. `run_mutation()`  
   生成变异配置，底层使用 `utils/runtime/mm_mutation/mm_mutator.py`

2. `run_pta_verify()`  
   在 PTA 环境下执行验证，调用对应的 `mm_pta_<model>.sh`

3. `run_msa_verify()`  
   在 MSA 环境下执行验证，调用对应的 `mm_msa_<model>.sh`

4. `analyze_results()`  
   对 PTA / MSA 的运行结果做分析与对比

### 2.2 模型侧执行视角

从多模态模型本身的运行逻辑看，一轮 Task6 通常仍对应下面三步：

1. 根据原始模型配置生成变异结果；
2. 以 `MM_MODEL` 为入口，调用 PTA 侧预训练 / 推理脚本执行验证；
3. 以同样的 `MM_MODEL`，调用 MSAdapter 侧脚本执行验证。

因此，Task6 的接入可以概括为三层：

1. 扩展 PTA / MSA 运行脚本；
2. 验证哪些参数可以安全参与整网变异；
3. 扩展变异参数池与配置生成逻辑。

---

## 3. 新增模型的最小接入路径

### 3.1 准备模型配置文件

建议在 `assets/mm_configs/` 下新增模型配置文件：

```text
assets/mm_configs/
├── model_<your_model>.json
└── data_<your_model>.json
```

其中：

- `model_<your_model>.json`：模型配置
- `data_<your_model>.json`：数据配置（训练类模型需要）

在更传统的多模态执行链路中，`MM_MODEL` 也可能直接指向类似下面的原始模型配置：

```python
MM_MODEL="./examples/cogvideox/i2v_1.5/model_cogvideox_i2v_1.5.json"
```

无论路径如何组织，原则都一样：**Task6 的 PTA / MSA 执行必须读取同一份原始模型配置，只允许环境实现不同，不允许初始语义不一致。**

## 4. 扩展 PTA / MSA 运行脚本

### 4.1 创建 PTA 入口脚本

创建：

```text
scripts/runtime/mm_pta_<your_model>.sh
```

示例骨架：

```bash
#!/bin/bash
set -e

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
LMSV_ROOT="$(cd "$SCRIPT_DIR/../.." && pwd)"

if [ -z "$MM_MODEL" ]; then
    echo "ERROR: MM_MODEL environment variable not set"
    exit 1
fi

MINDSPEED_MM_PATH="/shared/mindspeed-mm"  # 指向 workspace root，自动推导 MindSpeed-MM 子目录

export PYTHONPATH="${MINDSPEED_MM_PATH}:${PYTHONPATH}"
export DATASET_ROOT="${DATASET_ROOT:-/data2/dataset}"

mkdir -p "${LMSV_ROOT}/tmp/task6"
TMP_MODEL_CONFIG="${LMSV_ROOT}/tmp/task6/model_config_<your_model>_pta_$(date +%s).json"

bash "${SCRIPT_DIR}/prepare_mm_config.sh" "${MM_MODEL}" "${TMP_MODEL_CONFIG}" "<your_model>" "pta"
export MM_MODEL="${TMP_MODEL_CONFIG}"

bash "${SCRIPT_DIR}/pta_<your_model>_real.sh"
```

### 4.2 创建 MSA 入口脚本

创建：

```text
scripts/runtime/mm_msa_<your_model>.sh
```

其组织方式与 PTA 脚本一致，但应切换到 MSA 环境。

### 4.3 创建真实执行脚本

建议同时创建：

- `scripts/runtime/pta_<your_model>_real.sh`
- `scripts/runtime/msa_<your_model>_real.sh`

可参考现有脚本：

- 推理类模型：`pta_opensora_real.sh`、`msa_opensora_real.sh`
- 训练类模型：`pta_cogvideox_real.sh`、`msa_cogvideox_real.sh`

### 4.4 保证 PTA / MSA 初始配置语义一致

这是 Task6 中最容易被忽略、但最关键的约束。  
PTA 与 MSA 的脚本实现允许不同，但以下内容必须一致：

- 使用同一份原始模型配置；
- 初始化时采用同样的模型结构与关键参数；
- 加载同样的输入数据语义；
- 只允许运行环境和启动方式存在差异。

在旧版多模态执行链路中，这一点尤其体现在 PTA / MSA 的分布式启动参数应保持语义对齐。例如：

PTA：

```bash
GPUS_PER_NODE=8
MASTER_ADDR=localhost
MASTER_PORT=29505
NNODES=1
NODE_RANK=0
WORLD_SIZE=$(($GPUS_PER_NODE*$NNODES))
```

MSAdapter：

```bash
NPUS_PER_NODE=8
MASTER_ADDR=localhost
MASTER_PORT=29550
NNODES=1
NODE_RANK=0
WORLD_SIZE=$(($NPUS_PER_NODE*$NNODES))
```

参数名称可以不同，但表达的分布式语义必须一致。

## 5. 注册模型到 Task6

在 `utils/task/task6.py` 中补充模型配置。例如：

```python
MODEL_CONFIGS = {
    "your_model": {
        "name": "YourModel",
        "base_config": "assets/mm_configs/model_your_model.json",
        "data_config": "assets/mm_configs/data_your_model.json",
        "pta_script": "scripts/runtime/mm_pta_your_model.sh",
        "msa_script": "scripts/runtime/mm_msa_your_model.sh",
        "mutation_output": "tmp/task6/mutation_results/your_model",
        "type": "train",  # 或 "inference"
    },
}
```

这一步决定了 Task6 是否真正认识该模型，而不是只是在脚本层面“看起来已经准备好”。

## 6. 变异参数扩展

### 6.1 先验证哪些参数可以安全变异

多模态模型往往需要加载预训练权重。  
因此，并不是所有结构参数都适合直接参与整网变异。一个基本原则是：

> **只让那些不会破坏现有权重对齐和关键维度关系的参数进入常规变异池。**

建议做法是：先针对单个参数做手工验证。  
即在模型原始 JSON 配置中手动修改目标参数，再直接运行 PTA / MSA 验证脚本：

- 如果脚本能够重新执行完成，则该参数可以考虑进入变异池；
- 如果一改就触发维度、权重或算子路径错误，则不应作为常规可变参数。

原始配置中，通常更适合优先考察的是 `predictor` 和 `diffusion` 下的直接参数。例如：

```json
{
  "predictor": {
    "model_id": "satdit",
    "dtype": "bf16",
    "num_layers": 42
  },
  "diffusion": {
    "model_id": "cogvideo_diffusion",
    "sigma_sampler_config": {
      "uniform_sampling": true,
      "num_idx": 1000
    },
    "denoiser_config": {
      "num_idx": 1000,
      "quantize_c_noise": false
    }
  }
}
```

### 6.2 扩展变异参数池

完成单参数验证后，再把可安全变异的字段加入参数池。旧版链路中，典型位置是：

```text
mm-new/net_mutation/mm_mutation_system.py
```

例如：

```python
mutable_params_pool = {
  'mlp_ratio': {'min_val': 2.0, 'max_val': 8.0, 'min_factor': 0.7, 'max_factor': 1.5},
  'num_res_blocks': {'enum': [2, 3, 4]},
  'quantize_c_noise': {'enum': [True, False]},
}
```

这三种写法分别表示：

1. **范围 + 比例因子扰动**
2. **枚举扰动**
3. **布尔开关扰动**

若存在额外约束关系，可在 `_select_and_mutate` 中补充判断逻辑。例如：

```python
if isinstance(constraints, dict) and 'enum' in constraints:
    enum_values = constraints['enum']
    if isinstance(original_value, bool) and all(isinstance(v, bool) for v in enum_values):
        new_value = not original_value
    else:
        candidates = [v for v in enum_values if v != original_value]
        new_value = random.choice(candidates) if candidates else original_value
```

### 6.3 不要把“能改”误认为“适合长期变异”

Task6 中有一类参数可能在某次试验里“恰好能跑”，但并不适合作为长期维护的变异参数，例如：

- 会破坏权重映射的结构参数；
- 会改变关键输入输出尺寸的参数；
- 会引发隐式数据流重组的参数。

因此，是否纳入变异池，建议以 **可重复运行** 和 **可长期维护** 为标准，而不是只看单次能否启动。

## 7. Task6 的验证方式

建议使用最小规模配置做接入验证。例如：

```bash
cd <lm-sv-root>/lmsv_rec
export TASK6_MODEL_NAME=your_model
export TASK6_TOTAL_ITER=1
export TASK6_TRAIN_ITERS=2
python -m utils.task.task6
```

建议至少检查以下内容：

- 变异配置是否生成；
- PTA 脚本是否正常启动；
- MSA 脚本是否正常启动；
- 结果分析阶段是否成功生成对比输出；
- 临时配置文件是否被正确写入 `tmp/task6/`

## 8. 可选：静态图 / MindFormers 支持

若 Task6 需要继续扩展到静态图或 `pta_mf` 链路，可进一步补充以下内容。

### 8.1 在 `model_support.py` 中放开模型支持

例如：

```python
TASK1_WEIGHT_CONVERT_SUPPORTED_MODELS = ("qwen3", "deepseekv3")
```

如果新增模型要支持静态图链路，应把它加入相应支持列表。

### 8.2 准备 MF 模板

在：

```text
assets/runtime/mf_templates/
```

下新增模型模板。例如：

```yaml
seed: 42
output_dir: '/dev/shm/checkpoints'
load_checkpoint: ''
load_ckpt_format: 'safetensors'
use_parallel: True
run_mode: 'train'

trainer:
  type: CausalLanguageModelingTrainer
  model_name: 'DeepseekV3'

runner_config:
  epochs: 2
  batch_size: 1
  gradient_accumulation_steps: 1
```

### 8.3 适配 MindFormers 新版本

原始资料中还指出，MindFormers `r1.8.0` 之后，`mindformers.tools` 中不再提供 `set_output_path` 等函数。

对应适配方式是在 `run_mindformer.py` 中把旧调用改为：

```python
os.makedirs(config.output_dir, exist_ok=True)
```

如果静态图链路依赖 MindFormers 新版本，这一步通常必须处理，否则会直接在运行时失败。

## 9. 常见问题

### 9.1 PTA / MSA 都写了脚本，但结果仍不可比

通常不是脚本能否启动的问题，而是**两边初始配置语义不一致**。优先检查：

- 是否真的读取了同一份 `MM_MODEL`
- 是否只替换了环境，而没有改动模型本体参数
- 数据路径与数据预处理是否一致

### 9.2 模型能跑，但一变异就崩

说明变异池中混入了不适合整网扰动的结构参数。应先退回单参数验证，再收缩变异范围。

### 9.3 Task6 能识别模型名，但启动时报脚本不存在

优先检查 `utils/task/task6.py` 中注册的脚本路径是否与实际文件一致。

### 9.4 新增了 MF 模板，但静态图链路仍不可用

优先检查：

- 是否放开了 `model_support.py`
- MF 模板是否完整
- MindFormers 版本兼容是否处理
- 上游权重转换是否真正支持该模型

---

## 10. 结论

Task6 的扩展重点不是单纯“补几个运行脚本”，而是建立一个完整闭环：

1. 模型配置可识别；
2. PTA / MSA 运行入口可调度；
3. 变异参数池只包含可长期维护的安全参数；
4. 结果分析能够建立可比性；
5. 如需静态图支持，再逐步补齐 MF 模板与版本兼容。

只有做到这一点，Task6 才能从“能跑一次”升级为“可持续扩展和维护”的整网多模态变异能力。
