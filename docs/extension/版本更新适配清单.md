# 版本更新适配清单（MindFormers / MSAdapter / 相关依赖）

本文档聚焦“依赖版本更新”场景：当 `mindformers`、`msadapter`、`MindSpeed-LLM`、`MindSpeed-Core-MS` 等组件升级后，三大部分（模块内、模块间、整网）分别需要进行的修改适配。


---


## 1. 模块内（Task2 / Task5）版本更新适配

### 1.1 动态图语言类模型（PTA + MSA）

依赖升级后重点修改：
- **子模块执行入口同步**：`load_and_forward_submodule-auto.py`（PTA）与 `load_and_forward_submodule.py`（MSA）保持同构修改；
- **子模块编号范围兼容**：若新版本新增层结构，更新 `genconf.py` / `webui.py` 的 `SUBMODULES` 范围校验；
- **参数命名适配**：若注意力/归一化字段改名，补参数别名映射，避免加载缺失；
- **日志判定规则微调**：新版本报错文本变化时，更新关键字匹配（`RuntimeError`、配置严格对齐失败等）。

建议验证：
- Task2 最小集：`TOTAL_ITER=1`、单模型单子模块；
- 对比 `res/submodule_execution_pta.csv` 与 `res/submodule_execution_msa.csv` 是否正常产出。

### 1.2 动态图多模态模型（Task5 / single module）

依赖升级后重点修改：
- **模块注册与构建器适配**：检查模块类初始化参数是否与新版本 API 对齐；
- **dtype/shape 默认行为适配**：新版本常见在 bf16/fp16 和广播规则上有变化；
- **变异 schema 收敛**：剔除升级后不再可变或会触发权重维度冲突的参数；
- **PTA/MSA 启动脚本映射校准**：确保分布式参数和运行参数仍等价。

建议验证：
- 先跑 `single_module_mutate.py` 小轮次；
- 再跑 Task5 单轮，确认前向/反向和日志采集正常。

### 1.3 静态图模型（MindFormers）

依赖升级后重点修改：
- **运行入口 API 兼容**：例如 `mindformers` 新版本下线函数时，替换为标准库实现；
- **已知适配点（r1.8.0）**：`set_output_path` / `set_strategy_save_path` 缺失，改为 `os.makedirs(..., exist_ok=True)`；
- **MF 子图执行分支**：检查 `sub_graph.py` 的输入 shape 处理是否仍匹配新算子行为；
- **权重加载策略**：升级后若 ckpt 加载策略变化，先用 `ENABLE_MF_WEIGHT_LOAD=false` 验证流程，再开启权重加载。

建议验证：
- 先跑 Task2 的 `pta_mf` 单轮；
- 核查 `res/submodule_execution_mf.csv` 与 `training_log_mf` 是否完整。

---

## 2. 模块间（Task3 / Task4）版本更新适配

### 2.1 动态图语言类模型（PTA + MSA）

依赖升级后重点修改：
- **Graph 构图字段兼容**：`TransformerConfig` 新字段/删字段会导致过滤后配置不全，需要补 `FIELD_ALIAS` 或前置转换；
- **参数加载对齐修复**：关注“attention 未加载参数样例”，定位命名规则变化；
- **双端图执行同步**：PTA 与 MSA 的 `load_and_forward_graph.py` 修改保持一致；
- **多卡启动参数修复**：升级后 `torchrun/msrun` 参数行为变化时，先恢复单卡链路再扩到多卡。

建议验证：
- Task3 单轮 + 1~2 个模型；
- 检查 `execution_pta.csv`、`execution_msa.csv` 与日志对齐情况。

### 2.2 动态图多模态模型（Task4 / mutate.py）

依赖升级后重点修改：
- **模板前向接口适配**：新版本模块前向签名变化时，更新 Template 的调用参数；
- **模块池配置清洗规则**：`config_preprocess` 中 dtype 和结构对齐规则需重新核验；
- **随机组合约束修正**：新版本下某些组合可能不再合法，需补约束或屏蔽；
- **分布式执行参数重配**：PTA 与 MSA 的多机参数映射重新对齐。

建议验证：
- 先只注册一个模板做回归；
- 再恢复全模板随机组合。

### 2.3 静态图模型（MindFormers）

依赖升级后重点修改：
- **MF Graph 节点语义兼容**：如 decoder/embedding 之外新增节点类型，需补构图和执行分支；
- **对齐字段集合更新**：`ATTENTION_ALIGN_FIELDS`、`DECODER_CRITICAL_ALIGN_FIELDS`、`DECODER_FOCUS_FIELDS` 跟随新版本参数集更新；
- **转换链路检查**：`pth -> npz -> ckpt` 每一步都要验证文件完整性和加载可用性；
- **严格开关重校准**：新版本默认值变化后，严格对齐开关可能误报，需校准阈值和判定逻辑。

建议验证：
- Task3 的 `pta_mf` 小样本轮次；
- 确认 `res/execution_mf.csv`、`training_log_mf`、对齐结论一致。

## 3. 整网（Task1 / Task6）版本更新适配

### 3.1 动态图语言类模型（Task1）

依赖升级后重点修改：
- **模型模板与参数映射**：`pretrain_mutated_<model>.sh` 中关键参数位要覆盖新版本必需参数；
- **变异写回逻辑兼容**：`parallel_mutate/main.py` 的参数回填规则需识别新参数；
- **tokenizer 参数提取兼容**：`convert_pretrain_script.py` 对新脚本格式要可解析；
- **最小闭环优先**：先保证 `pta_msa` 稳定，再推进 `pta_mf`。

建议验证：
- 检查 `mutating-1.json`、PTA 脚本、MSA 脚本三者参数一致性；
- 再看训练日志与对齐结果。

### 3.2 动态图多模态模型（Task6 / mm-new）

依赖升级后重点修改：
- **模型配置 JSON 兼容**：升级后先验证参数是否仍可变且不破坏权重维度；
- **可变参数池重筛**：移除会触发新版本运行错误的参数，新增可安全变异参数；
- **PTA/MSA 入口脚本同步**：检查路径、环境变量、分布式参数在新版本下是否仍生效；
- **异常策略保持稳定**：继续使用“PTA 失败回滚、MSA 失败记录问题”的策略，避免无效突变污染结果。

建议验证：
- 每个模型先跑 `TOTAL_ITER=1`；
- 再按模型类型（训练/推理）分别扩大迭代。

### 3.3 静态图模型（Task1 的 pta_mf）

依赖升级后重点修改：
- **MF 模板升级**：同步新版本 `mindformers` 配置结构；
- **参数映射升级**：补 `mf_converter.py` 的 `ARG_MAPPING`；
- **模型支持清单更新**：`model_support.py` 中更新可转换模型和别名；
- **上游转换器验证**：确认 `convert_mg2hf` 对目标模型和当前版本可用。

建议验证：
- 先 `ENABLE_MF_WEIGHT_LOAD=false` 跑通流程；
- 再打开权重转换与加载，检查 loss 对齐与日志。
