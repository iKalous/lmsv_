# Task4 扩展说明：多模态模块间组合变异扩展

## 1. 文档目的

本文面向后续开发者，说明如何扩展 **Task4 多模态模块间组合变异**。  
Task4 的目标是：**把不同模块类型按模板组合成新的多模态模型，并通过前向 / 反向执行验证组合结构是否可运行**。

在当前设计中，Task4 的主流程由 `mutate.py` 驱动，核心依赖：

- `modules.json`：定义模块池
- `modules/*`：定义模块实现与注册机制
- `modules/pool.py`：维护模块池与构建逻辑
- `templates/*`：定义模块组合模板与前向路径

---

## 2. Task4 的整体思路

从扩展角度看，Task4 通常分成三层：

1. **扩展一个新的模块类型**  
   例如新增 `image_encoder`、`video_encoder`、`ae` 等。

2. **在某个模块类型下扩展一个具体模块**  
   例如在 `image_encoder` 下新增 `llava`。

3. **扩展一个新的模板**  
   让不同模块能够按新的组合方式接入 `mutate.py` 主流程。

如果这三层没有打通，新增模块即使写进了代码，也很难真正被 Task4 选中并参与组合验证。

---

## 3. 扩展一个新的模块类型

以下以 `image_encoder` 为例说明。

### 3.1 新增模块类型实现文件，定义基类与注册表

在 `modules/` 下新增对应文件，例如 `modules/image_encoder.py`。  
该文件至少应包含：

- 类型基类，例如 `ImageEncoder`
- 构建器字典，例如 `IMAGE_ENCODER_BUILDERS`
- 注册装饰器，例如 `@register_image_encoder(...)`
- 该类型的核心接口，例如 `encode()`

示例：

```python
IMAGE_ENCODER_BUILDERS = {}

def register_image_encoder(*names: str):
    def decorator(cls):
        for name in names:
            IMAGE_ENCODER_BUILDERS[name] = cls
        return cls
    return decorator

class ImageEncoder:
    def __init__(self, name: str, config: dict):
        self.name = name
        self.config = config

    def _build(self):
        pass

    def encode(self, images):
        pass
```

这里最关键的不是类名，而是要形成一套稳定的“注册 + 构建 + 调用”契约。后续模板层只应该依赖这些稳定接口，而不应直接耦合具体实现细节。

### 3.2 在 `modules/pool.py` 中增加对应 DictPool

Task4 的模块选择和实例化依赖模块池。  
因此新增类型后，需要在 `modules/pool.py` 中增加对应的 DictPool。

示例：

```python
class ImageEncoderDictPool:
    def __init__(self):
        self.image_encoders = {}

    def register_one(self, name: str, config: dict):
        self.image_encoders[name] = config

    def random_choice(self) -> dict:
        name = secrets.choice(list(self.image_encoders.keys()))
        return {name: self.image_encoders[name]}

    def build(self, name: str, config: dict) -> ImageEncoder:
        EncoderClass = IMAGE_ENCODER_BUILDERS[name]
        return EncoderClass.build(name, config)
```

如果新增的是 `ae` 等其他类型，也应采用同样模式，例如：

- `AEDictPool`
- `AE_BUILDERS`
- `register_ae`

### 3.3 在 `modules.json` 中建立顶层键

`mutate.py` 会从 `modules.json` 读取模块池，因此必须补齐该类型对应的顶层键。

例如 `image_encoder` 对应：

```json
{
  "image_encoders": {
    "llava": {
      "vision_encoder": { "...": "..." },
      "vision_projector": { "...": "..." }
    }
  }
}
```

建议统一使用复数形式作为顶层键，例如：

- `text_decoders`
- `image_encoders`
- `video_encoders`
- `aes`

### 3.4 在 `mutate.py` 中注册该类型

仅仅在 `modules.json` 中写了配置还不够，主流程必须真正把该类型注册进运行时的模块池。

示例：

```python
def register_all_modules(all_modules, args):
    text_decoders = all_modules["text_decoders"]
    image_encoders = all_modules["image_encoders"]

    for name, config in text_decoders.items():
        TEXT_DECODER_DICT_POOL.register_one(name, config)
    for name, config in image_encoders.items():
        IMAGE_ENCODER_DICT_POOL.register_one(name, config)
```

如果新增的是 `ae`，则应继续扩展：

```python
aes = all_modules["aes"]
for name, config in aes.items():
    AE_DICT_POOL.register_one(name, config)
```

### 3.5 更新模板，让新类型真正参与组合

完成注册后，还需要让模板能够：

1. 选中该类型；
2. 构建该类型实例；
3. 在前向过程中调用该类型的核心接口。

例如现有 `templates/image_model_template.py` 中，`image_encoder` 的标准使用方式就包括：

- `select_modules()` 中随机抽取 `IMAGE_ENCODER_DICT_POOL`
- `instantiate()` 中构建实例
- `forward()` 中调用 `instance.image_encoder.encode(images)`

如果模板不使用该类型，那么这个类型即使注册成功，也不会出现在最终组合图中。

## 4. 在已有模块类型下扩展一个具体模块

以下以在 `image_encoder` 下新增 `llava` 为例说明。

### 4.1 在实现文件中注册具体模块

在 `modules/image_encoder.py` 中实现子类，并通过装饰器注册名称：

```python
@register_image_encoder("llava")
class LLavaImageEncoder(ImageEncoder):
    @classmethod
    def build(cls, name: str, config: dict) -> "ImageEncoder":
        return cls(name, config)

    def __init__(self, name: str, config: dict):
        super().__init__(name, config)
        self._build()

    def encode(self, images):
        return self.encoder(images)
```

这里的关键约束有三个：

- 装饰器中的名字必须与 `modules.json` 中键名一致；
- `build()` 最好保持统一签名；
- `encode()` 的输出形状必须满足下游融合策略要求。

### 4.2 在 `modules.json` 中新增具体配置

例如：

```json
{
  "image_encoders": {
    "llava": {
      "vision_encoder": {
        "model_id": "clip",
        "num_layers": 23,
        "hidden_size": 1024,
        "image_size": 336,
        "params_dtype": "fp32"
      },
      "vision_projector": {
        "model_id": "mlp",
        "num_layers": 2,
        "input_size": 1024,
        "hidden_size": 4096,
        "params_dtype": "fp32"
      }
    }
  }
}
```

### 4.3 检查配置预处理逻辑

`mutate.py` 中的 `config_preprocess()` 会递归处理配置，例如：

- 把 `params_dtype` 从字符串转成 `torch.dtype`
- 处理 `vision_encoder` / `vision_projector` 等嵌套字段
- 自动对齐 `vision_projector.input_size = vision_encoder.hidden_size`

因此新增具体模块时，必须确认：

- 是否依赖特殊字段；
- 是否会被默认预处理逻辑改坏；
- 关键尺寸约束是否仍然成立。

### 4.4 验证能否被随机选中并正常前向

常用验证命令：

```bash
python mutate.py
```

重点检查：

- 日志中是否出现新模块名，如 `image encoder: llava`
- 是否能完成 `forward -> loss -> backward`
- 是否产出 `configs/round_*.json` 与 `dots/graph_round*.dot`

## 5. 扩展一个新的组合模板

当现有模板不能覆盖目标测试场景时，需要新增模板。

### 5.1 在 `templates/` 下新增模板类

建议继承 `Template`，至少实现：

- `select_modules()`
- `instantiate()`
- `forward()`
- `dump_graph()`

示例骨架：

```python
from templates.template import Template, MMInstance
from modules.pool import TEXT_DECODER_DICT_POOL, IMAGE_ENCODER_DICT_POOL

class YourTemplate(Template):
    def __init__(self):
        super().__init__("your_template")
        self.text_decoder_name = None
        self.text_decoder_config = None
        self.image_encoder_name = None
        self.image_encoder_config = None

    def select_modules(self):
        td = TEXT_DECODER_DICT_POOL.random_choice()
        self.text_decoder_name = list(td.keys())[0]
        self.text_decoder_config = td[self.text_decoder_name]

        ie = IMAGE_ENCODER_DICT_POOL.random_choice()
        self.image_encoder_name = list(ie.keys())[0]
        self.image_encoder_config = ie[self.image_encoder_name]

    def instantiate(self) -> MMInstance:
        instance = MMInstance(name=self.name, config={}, template=self)
        return instance

    def forward(self, instance: MMInstance, *args, **kwargs):
        return ...
```

### 5.2 模板只依赖稳定接口

模板中应尽量只依赖模块基类暴露的稳定接口，而不要直接依赖模块内部实现细节。  
例如：

- text decoder：优先调用 `embedding()`、`decode()`
- image encoder：优先调用 `encode()`

这样做的好处是：后续新增新的 encoder / decoder 时，只要实现接口契约，就可以复用已有模板。

### 5.3 在主流程中注册新模板

在 `mutate.py` 的 `register_all_templates()` 中注册：

```python
from templates.image_model_template import ImageModelTemplate
from templates.your_template import YourTemplate

def register_all_templates():
    TEMPLATE_REGISTRY.register(ImageModelTemplate())
    TEMPLATE_REGISTRY.register(YourTemplate())
```

### 5.4 验证模板是否真正生效

执行：

```bash
python mutate.py
```

重点观察：

- 日志中是否出现新模板名；
- 是否完成 `select -> instantiate -> forward -> backward`
- 是否生成对应配置和图结构文件

如果只想验证新模板，可临时只注册这一个模板，先通过功能回归后再恢复随机选择。

## 6. Task4 的验收建议

建议至少完成以下三类验收：

### 6.1 类型级验收

确认新模块类型已经完成：

- 实现文件
- DictPool
- `modules.json`
- `mutate.py` 注册

### 6.2 模块级验收

确认新模块实例能够：

- 被随机选中
- 正常构建
- 正常参与前向 / 反向

### 6.3 模板级验收

确认新增模板能够：

- 正常选模块
- 正常实例化
- 正常导出组合图
- 在真实运行中不出现接口不匹配

---

## 7. 常见问题

### 7.1 报错 `Invalid image encoder: xxx`

说明模块实现类没有正确注册，或者注册名与 `modules.json` 中键名不一致。

### 7.2 模块已经写入 `modules.json`，但从未被选中

优先检查：

- 是否在 `mutate.py` 中注册到了对应 DictPool；
- 是否有模板真正去选择和使用这个类型。

### 7.3 组合后 shape 不匹配

优先检查：

- `vision_projector.input_size`
- `vision_encoder.hidden_size`
- `encode()` 输出是否符合模板中的融合策略要求

### 7.4 dtype 不匹配

优先检查 `params_dtype` 与模板生成的输入张量 dtype 是否一致。

---

## 8. 结论

Task4 的扩展重点不在于“把一个模块写进仓库”，而在于让这个模块真正进入 **组合选择、实例化和模板前向** 三个环节。

只有当这三层都打通后，一个新增模块才算真正进入了多模态模块间组合变异流程。
