# Task5 扩展说明：多模态模块内组件变异扩展

## 1. 文档目的

本文面向后续开发者，说明如何扩展 **Task5 多模态模块内组件变异**。  
Task5 的目标是：**固定单一模块类型，在配置空间内持续扰动其内部参数，并逐轮验证该模块在变异后是否仍可稳定运行**。

Task5 的主流程由 `single_module_mutate.py` 驱动。与 Task4 相比，它关注的不是模块之间如何组合，而是**单个模块自身的配置扰动是否可执行、可回归、可复现**。

---

## 2. Task5 的前置条件

在开始扩展 Task5 之前，建议先确认目标模块已经具备以下前提：

1. 模块已经在 `modules/*` 中实现；
2. 模块已经注册到 `modules/pool.py` 与 `modules.json`；
3. 模块已经能够在 Task4 或最小前向路径中正常运行。

原因很直接：  
Task5 不负责“从零发明一个模块”，而是在已有模块可运行的前提下，对其配置做连续扰动和回归验证。如果模块本身尚未能被构建并执行，那么 Task5 的问题面会被无限放大。

---

## 3. Task5 的基本工作流

Task5 至少涉及两类扩展：

1. **配置变异规则扩展**  
   决定一个模块的哪些字段可以变、怎么变、取值边界是什么。

2. **单模块模板扩展**  
   决定系统如何选择该模块、读取与更新其配置，以及如何用最小前向路径验证变异结果。

对应的核心文件通常是：

- `single_module_mutate.py`
- `single_module_mutate_dict.json`
- `templates/single_*_template.py`

---

## 4. 配置变异规则扩展

### 4.1 在 `single_module_mutate_dict.json` 中补齐 schema

`single_module_mutate.py` 会通过 `SingleModuleMutator(schema_path=...)` 读取变异规则，然后在每一轮迭代中执行：

```python
mutated_config = single_mutator.mutate(
    module_type=module_type,
    base_config=current_config,
    mutation_num=3,
)
```

因此，若要让某个模块进入 Task5，首先必须在 schema 中为该模块类型定义可变字段及其范围。

### 4.2 常见的规则表达方式

常见有三类：

1. **连续 / 整数范围扰动**
   - `min_factor`
   - `max_factor`
   - `min_val`
   - `max_val`

2. **枚举扰动**
   - `enums`

3. **临时禁用某个字段**
   - `enabled: false`

示例：

```json
{
  "text_decoder": {
    "num_layers": {
      "min_factor": 0.5,
      "max_factor": 2.0,
      "min_val": 4,
      "max_val": 128
    },
    "attention_dropout": {
      "enums": [0.0, 0.1, 0.2, 0.3]
    }
  },
  "image_encoder": {
    "hidden_dropout": {
      "enums": [0.0, 0.05, 0.1]
    },
    "add_qkv_bias": {
      "enums": [true, false]
    }
  }
}
```

如果新增的是全新模块类型，例如 `ae`，则必须在 schema 顶层增加对应键，例如 `"ae"`。否则 `SingleModuleMutator` 根本无法命中该类型的配置。

### 4.3 变异规则设计建议

定义规则时，不要只看“参数是否存在”，更要看“这个参数改完后模块还能不能跑”。  
建议遵循以下原则：

- 约束范围尽量贴近真实模型边界；
- 优先选择已知可扰动、但不破坏关键结构对齐的参数；
- 对会直接破坏维度、头数或投影关系的参数保持谨慎。

---

## 5. 单模块模板扩展

### 5.1 模板要完成什么

Task5 的单模块模板至少需要完成三件事：

1. 从模块池选择一个基线模块；
2. 支持外部读取和写回该模块配置；
3. 用最小前向路径验证模块在变异后仍可运行。

现有模板可以参考：

- `templates/single_text_decoder_template.py`
- `templates/single_image_encoder_template.py`

### 5.2 建议实现的最小接口

单模块模板建议至少实现以下接口：

```python
class SingleXXXTemplate(Template):
    def get_module_type(self) -> SupportedModules: ...
    def get_module_name(self) -> str: ...
    def get_module_config(self) -> dict: ...
    def set_module_config(self, module_config: dict): ...
```

这四个接口分别对应：

- 当前模板服务的模块类型；
- 当前模块名称；
- 当前模块配置；
- 更新后的模块配置回写。

如果缺少这组接口，Task5 很难形成“读取配置 -> 变异 -> 回写 -> 验证”的闭环。

### 5.3 在 `single_module_mutate.py` 中注册模板

模板实现完成后，需要在 `register_single_templates()` 中注册：

```python
def register_single_templates():
    TEMPLATE_REGISTRY.register(SingleTextDecoderTemplate())
    TEMPLATE_REGISTRY.register(SingleImageEncoderTemplate())
    # TEMPLATE_REGISTRY.register(SingleAETemplate())
```

如果新增的是全新模块类型，也应在这里补充对应模板。

### 5.4 支持 `--type` 精确筛选

如果需要通过命令行精确筛选模块类型，还要确保：

- `get_module_type()` 返回值与 `SupportedModules` 枚举一致；
- `_parse_type_to_supported_module()` 能正确解析你的类型别名。

否则即使模板已经注册，命令行按类型筛选时也可能完全找不到。

---

## 6. 运行验证

常用验证命令示例：

```bash
python single_module_mutate.py --type image_encoder --rounds 3 --iterations 20
```

建议重点检查以下结果：

- 日志中是否出现目标模块类型和模板名；
- 每轮迭代是否都能完成 `forward -> loss -> backward`；
- `results/_single_module/.../configs/` 下是否生成配置快照；
- 每次变异后的配置是否真正发生变化，而不是被回写逻辑覆盖掉。

---

## 7. 推荐接入顺序

为了减少排障成本，建议按下面顺序推进：

1. 先确保目标模块已能在最小前向路径中正常运行；
2. 再在 `single_module_mutate_dict.json` 中补变异规则；
3. 再实现并注册单模块模板；
4. 最后使用 `--type` 启动小规模验证。

这样可以把问题明确区分为三类：

- 模块本身不能跑；
- schema 没命中；
- 模板回写与执行链路有问题。

---

## 8. 常见问题

### 8.1 schema 已写，但参数就是不变

优先检查：

- 模块类型键是否写对；
- 该字段是否真的存在于当前模块配置；
- 该字段是否被后续逻辑回写覆盖。

### 8.2 模板注册了，但 `--type` 找不到

优先检查：

- `get_module_type()` 是否与 `SupportedModules` 对齐；
- `_parse_type_to_supported_module()` 是否支持你的类型别名。

### 8.3 变异后前向失败

通常说明变异规则过于激进。优先收窄：

- 层数范围
- dropout 枚举
- 偏置开关
- 其他会影响维度和算子路径的字段

### 8.4 结果目录没有配置快照

说明流程大概率在变异后执行验证前就已经失败。应优先查看运行日志，而不是只看结果目录。

---

## 9. 结论

Task5 的关键不是“随机改几个参数”，而是建立一个稳定的单模块回归流程：

1. 能读到模块配置；
2. 能按规则生成有效变异；
3. 能把新配置写回模块；
4. 能用最小执行路径验证该模块仍然可运行。

当这四步形成闭环后，Task5 才算真正具备可维护的扩展能力。
