# Task3 扩展说明：模块间新模块接入

## 1. 文档目的

本文面向后续开发者，说明如何把新的模块能力接入 **Task3 模块间变异**。  
Task3 的目标是：**基于多个模块节点构建组合图，在更高一层的结构级别验证模块拼接后的执行与对齐情况**。

本文按两条链路展开：

- 动态图链路：`pta_msa`
- 静态图链路：`pta_mf`

---

## 2. Task3 的基本分层

Task3 的接入问题，建议按以下四层排查：

1. **配置入口层**  
   `genconf.py` / `webui.py` / `config.json` 是否能接收并传递新模块参数。

2. **任务编排层**  
   `utils/task/task3.py` 是否将参数传给正确的图执行脚本。

3. **图构建层**  
   模块配置能否被图构建逻辑正确实例化为节点和边。

4. **对齐校验层**  
   PTA、MSAdapter、MindFormers 链路是否能加载并执行该组合图。

---

## 3. 动态图链路扩展（`pta_msa`）

### 3.1 适用范围

动态图模块间扩展主要涉及：

- `utils/task/*`
- `utils/runtime/mutate_and_forward/*`
- `assets/runtime/*`
- 配置入口：`genconf.py` / `webui.py` / `config.json`

图构建核心文件：

- `utils/runtime/mutate_and_forward/core/graph.py`

执行与校验核心文件：

- PTA：`utils/runtime/mutate_and_forward/load_and_forward_graph.py`
- MSAdapter：`utils/runtime/ms_mutate_and_forward/load_and_forward_graph.py`

### 3.2 接入步骤

#### 步骤 1：准备模型模板配置

新模型需要扩展到：

```text
assets/runtime/model_config/<model>.yaml
```

Task3 会根据用户给定的模块类型，实例化若干个 TransformerBlock（可视为 decoder 层），然后再将它们进行组合与拼接。

#### 步骤 2：补齐 `TransformerConfig` 字段兼容

在 `Graph.load(...)` 中，系统会过滤掉不属于 `TransformerConfig` dataclass 的字段。如果新模块依赖的关键字段在过滤时被丢掉，就需要补转换或映射逻辑。

典型逻辑如下：

```python
valid_fields = set(TransformerConfig.__dataclass_fields__.keys())
filtered_cfg = {k: v for k, v in raw_cfg.items() if k in valid_fields}
unknown_fields = set(raw_cfg.keys()) - valid_fields
```

常见做法是在过滤前先做一次键名映射：

```python
FIELD_ALIAS = {
    "num_heads": "num_attention_heads",
    "eps": "layernorm_epsilon",
}
raw_cfg = {FIELD_ALIAS.get(k, k): v for k, v in raw_cfg.items()}
```

这个步骤的重点不是“字段尽量多”，而是确保 **图构建真正依赖的字段** 不会在进入 `Graph.load(...)` 前被误删。

#### 步骤 3：验证参数加载是否完整

如果图能构建出来，但运行时数值或权重异常，优先检查日志中的参数加载信息。建议重点关注：

- `attention参数加载统计`
- `attention未加载参数样例`

若出现系统性未加载，通常优先排查：

- 权重转换产物是否正确；
- 参数命名是否与图节点结构对齐；
- 模块节点的组织方式是否与期待的一致。

### 3.3 动态图链路检查清单

#### 配置检查

- `COMPARE_MODE=pta_msa`
- 模型名可被入口接受
- Task3 相关参数可被入口接受

#### 任务调用检查

- `task3.py` 是否调用 `load_and_forward_graph.py`
- MSAdapter 图执行链路是否同步启用

#### 结果文件检查

- `res/execution_pta.csv`
- `res/execution_msa.csv`
- `res/training_log_pta/training_log-<iter>.csv`
- `res/training_log_msa/training_log-<iter>.csv`

#### 日志检查

- `output/<timestamp>/iters/iter_i/runtime_logs/pta_iter{i}.log`
- `output/<timestamp>/iters/iter_i/runtime_logs/msa_iter{i}.log`

建议重点搜索：

- `RuntimeError`
- `attention配置严格对齐失败`

## 4. 静态图链路扩展（`pta_mf`）

### 4.1 适用范围

静态图模块间扩展主要涉及：

- `utils/task/*`
- `utils/runtime/mf_mutate_and_forward/*`
- `assets/runtime/*`
- 配置入口：`genconf.py` / `webui.py` / `config.json`

图构建核心文件：

- `utils/runtime/mf_mutate_and_forward/graph.py`

执行与校验核心文件：

- `utils/runtime/mf_mutate_and_forward/load_and_forward_graph.py`

### 4.2 接入步骤

#### 步骤 1：先确认节点语义

当前 `graph.py` 中通常把：

- `node_id = 0` 视作 `embedding`
- `node_id > 0` 视作 `mutated_decoder`

如果新增的是“非 decoder / embedding”类型节点，就不能继续沿用原有默认逻辑，而应显式扩展节点语义。

默认逻辑示意：

```python
node = Node(config=init_config, index=node_id)
node.str_op = "mutated_decoder" if node_id > 0 else "embedding"

if node.str_op == "embedding":
    node.block = LanguageModelEmbedding(...)
else:
    node.block = TransformerBlock(...)
```

如果需要新增例如 `adapter` 节点，建议改成：

```python
if node_id == 0:
    node.str_op = "embedding"
elif node_type == "adapter":
    node.str_op = "adapter"
else:
    node.str_op = "mutated_decoder"

if node.str_op == "adapter":
    node.block = MyAdapterBlock(node.config)
```

同时在 `construct(...)` 中增加相应执行分支：

```python
if cur_node.str_op == "embedding":
    output = cur_block(input_ids=input_ids, position_ids=position_ids)
elif "decoder" in cur_node.str_op:
    output = cur_block(input_data, attention_mask)
elif cur_node.str_op == "adapter":
    output = cur_block(input_data)
```

#### 步骤 2：补齐 `TransformerConfig` 字段兼容

与动态图链路一致。如果新节点依赖的字段不在 `TransformerConfig` dataclass 中，需要在构图前补做键名映射或字段转换：

```python
valid_fields = set(TransformerConfig.__dataclass_fields__.keys())
filtered_cfg = {k: v for k, v in raw_cfg.items() if k in valid_fields}
unknown_fields = set(raw_cfg.keys()) - valid_fields
```

可先做：

```python
FIELD_ALIAS = {
    "num_heads": "num_attention_heads",
    "eps": "layernorm_epsilon",
}
raw_cfg = {FIELD_ALIAS.get(k, k): v for k, v in raw_cfg.items()}
```

#### 步骤 3：必要时扩展 PTA -> MF 的对齐字段集合

如果新增模块引入了会影响数值路径的关键配置，除了图构建本身，还要同步补对齐字段集合。

典型位置包括：

- `ATTENTION_ALIGN_FIELDS`（`graph.py`）
- `DECODER_CRITICAL_ALIGN_FIELDS`（`graph.py`）
- `DECODER_FOCUS_FIELDS`（`load_and_forward_graph.py`）

示例：

```python
ATTENTION_ALIGN_FIELDS = (
    "num_attention_heads",
    "num_query_groups",
    "kv_channels",
    "attention_dropout",
    "hidden_dropout",
    "normalization",
    "layernorm_epsilon",
    "masked_softmax_fusion",
    "attention_softmax_in_fp32",
    "apply_query_key_layer_scaling",
    "my_new_attention_field",
)

DECODER_CRITICAL_ALIGN_FIELDS = (
    "bias_dropout_fusion",
    "apply_rope_fusion",
    "context_parallel_algo",
    "use_flash_attn",
    "my_new_decoder_field",
)
```

```python
DECODER_FOCUS_FIELDS = (
    "hidden_size",
    "ffn_hidden_size",
    "num_attention_heads",
    "my_new_decoder_field",
)
```

#### 步骤 4：验证参数加载是否完整

若图结构可运行，但权重或数值路径存在问题，建议优先检查：

- `attention参数加载统计`
- `attention未加载参数样例`

同时确认：

- 权重转换产物是否完整（如 `pth -> npz -> ckpt`）
- 参数命名与 MF 节点结构是否对齐

### 4.3 静态图链路检查清单

#### 配置检查

- `COMPARE_MODE=pta_mf`
- `MF_ARGS_PATH` 指向有效模板
- 模型名与模块参数可被入口接受

#### 任务调用检查

- `task3.py` 是否调用 `load_and_forward_graph.py`

手工复现命令示例：

```bash
python utils/runtime/mf_mutate_and_forward/load_and_forward_graph.py \
  --load-path <mutating-json> \
  --args_path assets/runtime/mf_templates/your_model.yaml \
  --train-iters <iters>
```

#### 结果文件检查

- `res/execution_mf.csv`
- `res/training_log_mf/training_log-<iter>.csv`

#### 日志检查

- `output/<timestamp>/iters/iter_i/runtime_logs/mf_iter{i}.log`

建议重点搜索：

- `RuntimeError`
- `attention配置严格对齐失败`
- `decoder配置严格对齐失败`

#### 对齐开关（按需）

- `LMSV_ALIGN_ADD_QKV_BIAS`
- `LMSV_STRICT_ATTN_CONFIG_MATCH`
- `LMSV_STRICT_ATTN_PARAM_LOAD`
- `LMSV_STRICT_DECODER_CONFIG_MATCH`

---

## 5. 推荐接入顺序

Task3 的问题定位成本通常高于 Task2，因此建议始终遵循以下顺序：

1. 先在 Task2 打通单子模块；
2. 再迁移到 Task3，验证多节点串联行为；
3. 最后再打开严格对齐开关做回归门禁。

这样做可以显著减少“节点组合错误”和“单节点接入错误”混在一起时的排查成本。

---

## 6. 常见问题

### 6.1 节点能创建，但图执行失败

优先检查：

- 节点语义是否正确；
- `construct(...)` 是否覆盖了该节点类型；
- 节点输入输出接口是否匹配。

### 6.2 配置字段明明写了，但图里没有生效

优先检查：

- 是否被 `TransformerConfig` 字段过滤掉；
- 是否在构图前缺少字段别名映射。

### 6.3 PTA 能跑，MF 图执行失败

优先检查：

- `graph.py` 中节点语义是否扩展完整；
- 对齐字段集合是否同步更新；
- 权重转换和参数命名是否与 MF 节点对齐。

### 6.4 日志里大量“未加载参数样例”

通常说明不是单个参数缺失，而是**模块结构或命名体系整体不对齐**。这时应优先检查图节点的构建方式，而不是先去补零散参数。

---

## 7. 结论

Task3 的核心不在于“把一个新模块塞进图里”，而在于：

1. 让该模块在图结构层面有明确语义；
2. 让它在执行层面有匹配的输入输出分支；
3. 让 PTA / MSA / MF 三条链路都能对它进行一致验证。

如果这三层没有闭环，即使图能构造出来，也很难形成稳定可维护的 Task3 扩展能力。
